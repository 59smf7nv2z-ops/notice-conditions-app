# [단계 1/7] 기존 코드 정리와 회귀 테스트

## 맥락
이 저장소에는 이미 검증된 코드와 데이터가 있다.
- scripts/legacy/ : 건축물대장 표제부 일괄 조회 스크립트, 규칙 판정 코드, 공고 조건 추출 스크립트(LLM),
  정확도 계산 코드, 조건 파일, Streamlit 프로토타입
  - 판정 코드 검증 이력: 서울 종로구 청운동 359건을 번지 없이 일괄 조회해
    광주 동구 점검 조건(40년·3층 이하·200㎡ 미만)으로 판정 → 후보 65, 확인필요 36, 제외 258.
    표본 30건을 사람 판정과 비교해 일치 확인.
- data/ordinances/ : 지자체별 건축물관리 조례 CSV (220건 수집·분류 결과)
- data/notices/ : 공고 6건의 추출 결과와 사람이 확정한 정답
- (있으면) frontend_grok/ : grok 웹앱 소스. 화면 구성 참고용이며 이 단계에서 건드리지 않는다.

## 1단계: 읽고 보고 (코드 수정 금지)
위 파일을 모두 읽고 아래를 보고한 뒤 멈춰라. 내가 "진행"이라고 하면 2단계부터 수행한다.
1. 파일별 역할, 진입점, 외부 의존성
2. 판정 함수의 입력·출력 형태, 상태 이름, 사유 생성 방식
   - 특히 기존 "확인필요"에 무엇이 들어가는지:
     데이터 불확실(사용승인일 공란 등)만인지, 위원회 심사 같은 대장 외 조건도 포함하는지
3. 판정 기준일(경과연수 계산 기준 날짜)을 어디서 정하는지
4. 조건 파일 스키마(필드 목록과 예시 1개)
5. 조례 CSV 컬럼 목록과 샘플 3행, 규모규정 유형 컬럼의 고유값 목록
6. 공고 추출 프롬프트와 항목 정의가 있는 위치
7. 하드코딩된 키, 절대경로, 날짜 목록

## 2단계: 구조 이전
- .cursor/rules/project.mdc의 디렉터리 구조로 옮긴다. scripts/legacy/ 원본은 그대로 둔다.
- 판정 로직은 core/evaluator_legacy.py로 "그대로" 옮긴다. 로직 변경 금지, import 경로·키 로딩만 고친다.
- 조회 로직은 아직 옮기지 않는다(단계 3에서 이식).

## 3단계: 회귀 테스트
- tests/fixtures/cheongun_title.json : 청운동 표제부 원본 응답.
  기존 산출물이 있으면 그것을 쓰고, 없으면 scripts/capture_fixture.py로 한 번 조회해 저장한다.
  (테스트 픽스처 전용이며 앱 런타임 저장이 아니다. 실주소가 있으므로 저장소가 공개면 .gitignore에 넣는다.)
- tests/fixtures/sample30_truth.csv : 표본 30건의 대장PK와 사람 판정 결과.
- tests/test_regression_legacy.py :
  - 기존 광주 동구 조건 파일로 evaluator_legacy 실행 → 상태별 건수 65/36/258 일치
  - 표본 30건 상태 일치
  - 판정 기준일은 기존 결과를 만든 날짜로 고정한다. 오늘 날짜를 쓰면 경과연수가 바뀌어 테스트가 깨진다.
- 기존 공고 추출 정확도 계산 코드가 정답셋으로 다시 돌아가는지 확인하는 스모크 테스트
  (LLM 호출은 live 마크, 기존 추출 결과 JSON으로 정확도만 재계산하는 테스트는 기본 실행).
