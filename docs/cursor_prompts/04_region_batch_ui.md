# [단계 4/7] 지역 일괄 대조·결과 추출 + 안내문 + Streamlit 화면

## 목표
시·도 → 시·군·구 → 법정동(복수) 선택 → "조회·판정" 버튼 하나로 대장 수집과 판정을 자동으로 끝내고,
결과표·통계·내보내기·안내문까지 제공한다. 화면 구성은 기존 grok 웹앱의 4탭 구조를 따른다.

## 4-1 core/pipeline.py
- run_region(sigunguCd, bjdongCds, notice, ordinance, eval_date, raw_cache, progress) -> RegionResult
  - RegionResult: df, stats(상태별 건수), unmapped_structures, unmapped_uses, api_calls, warnings, failed_dongs
- raw_cache(dict)에 이미 있는 동은 재조회하지 않는다. 조건만 바뀌면 재판정만 한다.
- 동 하나가 실패해도 나머지는 계속하고 failed_dongs에 남긴다. QuotaError면 즉시 멈추고 부분 결과를 반환한다.

## 4-2 공고 조건 선택
- data/notices/의 검수된 공고 JSON 중 sigungu_codes에 해당 지역이 있는 것을 불러온다.
  여러 개면 접수 시작일이 최신인 것을 기본 선택하고 드롭다운으로 바꿀 수 있게 한다.
- 공고가 없으면 배너: "공고 없음 – 조례 기준 판정". 조례도 없으면 "법정 기준(30년)만 적용".
- 마감된 공고(is_expired)는 선택할 수 있지만 배너로 "접수 마감(YYYY-MM-DD) · 다음 공고 대비 참고용"을 띄우고 안내문 생성은 막는다.
- reviewed=False 공고는 "미검수" 배지, 내보내기 요약 시트에도 표시한다.
- "다른 지역 공고 적용(시험용)" 옵션: 다른 지역 공고를 강제로 적용. 결과 전체에 시험용 표시.
- 조건 편집기(사이드바): 담당자 수정은 세션에만 반영하고 "수정됨" 배지. 수정본은 JSON 다운로드로만 내보낸다.

## 4-3 Streamlit 앱 (app/main.py + 탭별 모듈)
상단 바 또는 사이드바: 시·도 / 시·군·구 / 법정동(multiselect) 선택, 공고 선택, 판정 기준일(기본 오늘), 조건 편집기.

- 탭1 공고문 분석 & 조건 추출: 이 단계에서는 저장된 공고 JSON 보기·편집과 원문 근거 표시만. 업로드 추출은 단계 6.
- 탭2 지역 일괄 대조 (이 단계의 핵심)
  - "조회·판정" 버튼 → 진행바(API 호출 수 / 총)
  - 법정동 "전체 선택" 시 estimate_calls 결과를 보여주고 확인 체크박스를 받은 뒤 실행
  - 통계 카드: 총 건물 수, 1차 후보, 확인필요, 조례만 충족, 비해당
  - 상태 필터 + 결과 표(st.dataframe, on_select="rerun", selection_mode="single-row")
  - 선택 행 상세: 대장 스펙, 조건별 비교표(조건 | 공고 기준 | 조례 기준 | 대장 값 | 결과), 확인필요 사유, 현장확인 체크리스트
  - expander: 미매핑 구조·용도 값과 건수, 실패한 동
- 탭3 안내문 및 결과 리포트 (4-5)
- 탭4 지도: 자리만 만들고 단계 5에서 구현

세션 상태
- st.session_state["raw"][(sigunguCd, bjdongCd)] = 대장 원본 DataFrame
- st.session_state["results"][(sigunguCd, bjdongCd, condition_hash)] = 판정 결과
- 여러 동을 차례로 조회하면 누적된다. "세션 데이터 지우기" 버튼 제공.
- 새로고침·세션 종료 시 사라지는 것이 정상 동작이다. 화면 하단에 "조회 데이터는 저장되지 않습니다" 안내.

## 4-4 내보내기 (core/export.py) — 메모리에서 생성, 디스크 저장 없음
- CSV(utf-8-sig)와 Excel
- Excel 시트: 요약(지역·공고명·검수 여부·조례명·판정 기준일·상태별 건수), 조건표(공고·조례 나란히 + 원문 근거),
  1차후보, 확인필요, 조례만충족, 비해당(선택), 미매핑값
- 컬럼: 지번주소, 도로명주소, 건물명, 동명, 상태, 사유, 확인필요 사유, 현장확인 항목, 사용승인일, 경과연수,
  지상층수, 지하층수, 연면적, 주구조(원문/표준), 주용도(원문/기타용도), 대장PK
- 파일명: {시군구}_{법정동 또는 "N개동"}_{YYYYMMDD}_판정결과.xlsx

## 4-5 안내문 (core/letters.py)
- 틀 방식: 공고·말투별 틀 1개 + 자리표시자
  {지번주소} {도로명주소} {사용승인일} {경과연수} {주구조} {주용도} {지상층수} {연면적}
  {접수기간} {신청방법} {접수처} {문의처} {제출서류}
- 내장 틀 3종(어르신 맞춤형 / 공식 행정문서형 / 알림톡·SMS형)을 코드에 둔다. LLM 없이도 동작해야 한다.
- make_template(notice, tone) -> str 인터페이스만 만든다. 기본 구현은 내장 틀 반환, LLM 연결은 단계 6.
- 틀 검증: 허용 목록 밖 자리표시자, 틀 안에 직접 쓴 수치(예: 숫자+㎡, 숫자+년) 금지.
- 표현 규칙: 1차 후보는 "지원 대상에 해당할 가능성이 높습니다", 확인필요는 "지원 대상에 해당할 수 있습니다".
  확정 표현 금지. 마지막 줄에 "발송 전 담당자 검토" 문구.
- SMS형은 바이트 수를 표시하고 90바이트를 넘으면 LMS 안내.
- 탭3 화면: 발송 대상 체크(1차 후보·확인필요), 말투 선택, 1건 미리보기, 일괄 생성 →
  .docx(건물별 페이지 나눔) + 대상 목록 CSV 다운로드.
- 수신자는 "{지번주소} 건축물 소유자(관리자)"로 쓴다. 소유자 성명·연락처는 이 시스템에 없으며
  구청 내부 시스템에서 결합한다고 화면에 안내한다.
