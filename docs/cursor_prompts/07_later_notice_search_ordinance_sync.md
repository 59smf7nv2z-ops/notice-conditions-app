# [단계 7/7, 후순위] 공고 자동 탐색과 조례 동기화
요구사항 1~3(단계 1~6)이 끝난 뒤 진행한다.

## 7-1 공고 탐색 (core/notice_hunter.py)
- 순서: data/notices의 검수된 공고 → 네이버 검색 API(뉴스 + 웹문서) → 없으면 조례 기준 판정 + 수동 업로드 안내
- 네이버 검색
  - 키를 발급받은 곳(네이버 개발자센터 또는 NAVER API HUB)에 따라 엔드포인트와 인증 헤더가 다르다.
    설정으로 분리하고 둘 다 지원한다.
  - 뉴스는 sort=date(최신순). 웹문서 검색에는 정렬 파라미터가 없다.
  - 하루 호출 한도 25,000회.
- 쿼리: "{시군구명} 소규모 노후건축물 안전점검" + 연도를 넣은 변형 1~2개
- 결과는 후보 링크 목록(제목, 출처, 날짜)으로만 보여준다. 사용자가 고른 링크만 본문을 가져와 단계 6 분류·추출로 넘긴다.
- 자동 추출 결과를 검수 없이 캐시에 저장하지 않는다(reviewed=False).
- 뉴스·보도자료 출처는 source_type=NEWS/PRESS_RELEASE로 표시하고 "원문 공고 확인 필요" 경고.
- robots.txt와 접근 제한을 존중한다. 첨부파일(HWP/PDF)은 링크만 보여주고 사용자가 내려받아 업로드한다.

## 7-2 조례 동기화 (scripts/sync_ordinances.py, LAW_API_OC)
- 법제처 Open API는 신청 때 등록한 IP에서만 동작한다 → 등록된 PC에서 수동 실행하는 운영자 스크립트로 만든다. 앱 런타임에서 부르지 않는다.
- 기존 220건 수집 스크립트를 재사용한다.
- 변경 감지: 자치법규 목록 조회로 시행일자·일련번호를 비교. 개정 시 일련번호(MST)가 바뀌는지 실제 응답으로 먼저 확인하고,
  바뀌면 자치법규ID(또는 이름+지자체) 기준으로 추적한다.
- 조문 분리는 줄 시작의 "제N조(" 패턴만 쓴다. 본문 속 인용("법 제15조제1항")에서 잘리지 않게 테스트한다.
- 변경 조문만 LLM으로 조건 초안 → 기존 CSV 대비 diff 리포트 → 사람이 승인해야 CSV 갱신.
